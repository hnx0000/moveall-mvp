사진·영상은 PostgreSQL DB에 원본을 넣지 않음
DB에는 파일 URL·소유자·게시물 연결·메타데이터만 저장하고, 실제 바이너리는 Object Storage에 저장합니다. GROOV에서는 이 영역이 장기적으로 가장 큰 저장/전송 비중이 될 가능성이 높습니다.
확정 아키텍처 결정
운영 DB Supabase PostgreSQL 회원 · 프로필 · 운동기록 · 게시물 · 댓글 · 팔로우 · 크루 · 챌린지 · 메달 · 포인트 · 신고/차단/관리 데이터
미디어 저장소 Supabase Storage → Cloudflare R2 초기에는 단순하게 시작하고 사진·영상 트래픽이 커지면 R2로 분리
설계 원칙
GROOV 백엔드는 Fastify API → PostgreSQL 구조를 유지합니다. Supabase는 현재의 PostgreSQL 운영 제공자로 사용하고, 애플리케이션 코드가 Supabase 전용 SDK에 과도하게 종속되지 않도록 DB 접근은 기존 PostgresStore 계층을 중심으로 유지합니다. 향후 필요하면 Neon, AWS RDS 등 다른 PostgreSQL로 이전 가능하게 설계합니다.
인프라 확장 계획
개발 · Supabase Free (PostgreSQL)→ 출시 · Supabase Pro (동일 DB)→ 성장 · PostgreSQL 유지 + 미디어만 Cloudflare R2
R2는 DB 교체가 아니라 사진·영상용 Object Storage 확장입니다. 회원·운동·소셜 데이터는 PostgreSQL 계열에 유지하는 방향.

AndroidHealth Connect지원 웨어러블/건강 앱 데이터 ↔ GROOV

현재 기술 결정 · 확정
DB는 Supabase PostgreSQL로 진행합니다. 출시 초기에는 Supabase Pro로 전환하고, 사용자 증가 시 DB를 R2로 바꾸는 것이 아니라 사진·영상 Object Storage만 Cloudflare R2로 확장합니다. PostgreSQL 중심 구조는 유지해 향후 인프라 이전 여지를 남깁니다.
한 줄 결론
“프로토타입”은 이미 지났고, 지금은 “운영 가능한 베타”로 넘어가는 구간입니다.
언어를 새로 고르는 단계가 아니라, 현재 TypeScript + Expo/React Native + Fastify + PostgreSQL 구조를 살리면서 운영 인프라를 붙이는 단계입니다.
