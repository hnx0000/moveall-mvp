# 업데이트 방향 도구 · 검토용 시안

현재 적용 범위: 기존 개발 대시보드의 사용자 검증 영역 가독성 개선 + 별도의 로컬 시안. 실제 앱 기능, 운영 데이터, 개발 우선순위 자동 적용은 변경하지 않았다.

## 기존 체크리스트의 역할

- 사람이 4개 사용자 유형의 시나리오 20개와 공통 조건 5개를 직접 확인한다.
- 체크·관찰 근거·상태·다음 검증 메모를 현재 브라우저에 저장한다.
- 근거 없이 ‘검증됨’으로 바꾸는 것을 제한한다. 앱을 실행하거나 자동 테스트·설문 분석·출시 판정을 수행하지 않는다.
- 온보딩 저장과 관리자 집계는 별도 구현이다. 운영 DB 마이그레이션과 실제 운영 집계 연결 여부는 이번 시안에서 확인·변경하지 않았다.

## 제안: 설문 → 후보 비교 → 판단 이력

`dashboard/direction-lab.html`에서 직접 체험한다. 개발 대시보드에도 시안으로 가는 링크만 추가했다.

1. **사용 목적 구성 확인**: 네 유형의 응답 수, 비율, 응답률, 건너뜀·미수집·제외 인원, 질문 버전과 가입 기간. 예시 인원 수정 또는 기존 집계 JSON 가져오기.
2. **다음에 검증할 후보 비교**: 기록·공유·성장·경쟁·개인 성취 후보별 대상 비중 + 관찰 불편 + 작업 규모를 함께 본다. 근거가 없으면 점수를 내지 않고 검증을 요구한다.
3. **판단 기록**: 후보, 이유, 성공 기준, 재검증일과 당시 자료 출처·집계를 저장한다. JSON으로 내보내 별도 보관한다. 자동 알림이나 개발 작업 생성은 하지 않는다.

### 계산은 투명한 시안 규칙

탐색 점수 = (대상 유형 응답 비중 × 40 + 불편 단계 × 20) ÷ 작업 규모.

- 불편 0–3단계, 규모 1–3. 계수는 검토용 가정이지 검증된 예측 모델이 아니다.
- 실제 관찰 근거와 작업 추정이 필요하다. 예시에 표시된 인원·불편·규모·관찰은 모두 가상이다.
- 단일 선택 설문이므로 후보 내 복수 수혜 유형은 합산하되, 후보끼리는 사용자가 겹친다. 후보 점수를 투자 비율로 해석하지 않는다.
- 기록 유실·개인정보 노출·핵심 기능 막힘은 점수를 무시하고 복구가 먼저다.
- 응답 30명·응답률 50% 경고선은 탐색용이며 대표성·유의성을 보장하지 않는다.
- 가입 목적만으로 실제 행동, 만족도, 예상 매출, 이탈 감소를 추정하지 않는다. 소수 유형도 동일한 기능을 이용한다.

## 자료 경계

- 시작 화면은 사용자 요청에 있던 42/31/8/19를 이용한 설명용 예시. 실제 현재 사용자 구성비가 아니다.
- 실제 집계는 기존 `GET /v1/admin/usage-purposes` 응답 형식의 JSON으로 수동 가져오기만 지원한다. 파일 출처는 자동 인증하지 않는다.
- 개인별 파일은 필요 없다. 인원 합계·기간·질문 버전을 검사하고 관련 없는 필드를 제거한다. `preview` 자료를 실제 가입자 자료로 승격하지 않는다.
- 자료를 바꾸면 예전 관찰·불편 가정을 자동 승계하지 않는다.
- 새로운 서버 연결, 토큰 수집, 개인정보 전송, 운영 DB 쓰기는 없다. 메모는 현재 브라우저에만 저장되고 브라우저 데이터 삭제 시 사라진다. 다른 기기와 동기화되지 않는다.

## 승인 후 연결할 수 있는 것

추천 도입 범위는 ① 관리자 전용 실제 집계 읽기 + ② 수동 관찰을 결합한 후보 비교 + ③ 판단 이력이다. 먼저 데이터의 운영 저장·권한·중복 제외를 확인한 뒤 연결한다.

그 다음에는 같은 질문 버전·비교 가능한 기간의 구성 변화와 검증 결과를 비교할 수 있다. 행동·재사용 데이터를 추가하려면 수집 목적·동의·이벤트 정의를 먼저 정해야 한다. 이번에는 추적기를 설치하지 않았다.

자동 배포, 탭 재배치, 사용자 기능 제한, 일정 작업 생성은 제안 범위에도 기본 포함하지 않는다. 최종 개발 결정은 사람이 한다.
