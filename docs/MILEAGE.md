# 마일리지 후속 설계

상태: `BACKLOG` — 현재 MVP에는 적립, 잔액 표시, 상품 할인 기능을 노출하지 않습니다.

## 목표

검증된 운동 기록에 마일리지를 부여하고, 추후 입점 브랜드의 운동용품 구매 시 할인으로
사용할 수 있게 합니다. 마일리지는 현금이 아니며, 사업 정책과 이용약관이 확정되기 전에는
사용자에게 적립을 약속하지 않습니다.

## 기본 원칙

- 잔액 숫자를 직접 수정하지 않고 모든 변동을 원장에 남깁니다.
- 운동 세션 하나에는 하나의 적립 요청만 허용합니다.
- 수동 입력만으로 만든 기록은 기본적으로 적립 대상에서 제외하거나 낮은 신뢰 등급으로
  분리합니다.
- 실제 워치, 지도, 시간, 거리 등 검증 가능한 증거가 연결된 기록부터 적립합니다.
- 적립 규칙은 버전을 부여해 과거 기록의 계산 근거를 보존합니다.
- 구매 취소와 반품 시 사용 마일리지를 복원하고, 적립 취소가 필요하면 반대 원장 항목을
  기록합니다.
- 관리자 조정, 만료, 사용, 취소도 삭제하지 않고 감사 가능한 사유를 남깁니다.

## 권장 데이터 모델

- `mileage_accounts`: 사용자별 계정과 사용 가능·대기 잔액의 계산 기준
- `mileage_ledger`: `EARN`, `REDEEM`, `REVERSE`, `EXPIRE`, `ADMIN_ADJUST` 원장
- `workout_verifications`: 기록 출처, 공급자 기록 ID, 검증 상태와 근거
- `reward_rules`: 종목, 거리·시간, 일/월 상한, 유효 기간을 포함한 버전 규칙
- `redemptions`: 주문, 브랜드 할인, 사용 원장과 취소 원장의 연결

잔액은 `mileage_ledger`의 확정 항목 합계로 계산하고, 성능이 필요할 때만 재계산 가능한
캐시를 추가합니다.

## 처리 흐름

1. 운동 기록을 완료합니다.
2. 외부 기록 ID와 세션 ID로 중복을 차단하고 거리·시간·출처를 검증합니다.
3. 조건을 통과하면 마일리지를 `PENDING`으로 적립합니다.
4. 이상 징후 검사가 끝나면 `CONFIRMED`로 전환합니다.
5. 브랜드 상품 주문 시 사용 가능 금액과 중복 할인 규칙을 확인한 뒤 차감 원장을 남깁니다.
6. 결제 취소·반품 시 기존 원장을 삭제하지 않고 복원 원장을 추가합니다.

## 구현 전 결정할 항목

- 종목별 적립률과 일·월 상한
- 수동 기록, 사진 인증, 워치 기록별 신뢰 등급
- 적립 대기 기간, 만료 기간, 부정 이용 판정과 이의 제기 절차
- 브랜드 부담과 플랫폼 부담의 정산 방식
- 쿠폰·프로모션·마일리지의 중복 할인 순서
- 부분 취소와 반품 시 복원 규칙
- 이용약관, 개인정보 처리, 표시·광고와 소비자 보호 관련 검토

## 현재 코드의 확장 지점

운동 세션의 `source`와 향후 웨어러블 공급자 기록 ID를 검증 입력으로 사용합니다. 실제
웨어러블 연동이 완료되기 전에는 운동 기록 API가 마일리지 원장을 생성해서는 안 됩니다.
구현 시 운동 저장 트랜잭션과 적립 요청을 중복에 안전하게 연결하고, 장애 재시도에도 같은
세션이 두 번 적립되지 않는 통합 테스트를 필수로 추가합니다.
