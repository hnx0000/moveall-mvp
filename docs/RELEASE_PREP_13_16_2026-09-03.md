# GROOV 13–16 출시 준비 보고서

작성일: 2026-09-03

## 결론

13–16번은 코드와 문서로 닫을 수 있는 범위까지 구현했다. 계정 삭제 연쇄, 고아 미디어 정리, 이미지 EXIF 제거, 업로드 실파일 검증, 게시물·댓글 신고, 차단 사용자 피드 제외, DB readiness, 암호화 백업·복원 훈련 명령, 운영 모니터 워크플로, 계정 삭제 공개 URL과 스토어 메타데이터 초안이 준비됐다.

법적 주체 정보, 외부 서비스별 국외 이전 세부, 실제 백업 Secret·복원용 DB, 크래시 수집 서비스, 스토어 서명·아이콘·최종 스크린샷·심사와 Google 테스트 인원은 코드만으로 승인할 수 없으므로 완료 처리하지 않는다.

## 검증 결과

- Prettier, ESLint, TypeScript 통과
- 계약 테스트 10개와 API 테스트 27개, 총 37개 통과
- API 빌드와 31개 정적 웹 경로 export 통과
- 추적·미추적 소스 Secret 검사 통과
- 이번 작업에서는 GitHub push와 공개 배포를 하지 않았다. 지원·계정 삭제 URL의 새 경로는 다음 배포 때 공개된다.
- 실제 운영 DB 백업/복원, 워크플로 Secret 등록, 실기기 EXIF·권한 검증과 스토어 제출은 미실행이다.

## 13. 데이터 보존·삭제·국외 이전 — 부분 완료

구현 완료:

- 앱 안의 계정 영구 삭제와 공개 `/legal/account-deletion` 안내 경로
- 계정 삭제 시 Supabase Storage 객체를 먼저 삭제하고 PostgreSQL 사용자와 종속 데이터를 `ON DELETE CASCADE`로 삭제
- 미완료 업로드와 게시물에서 분리된 미디어를 24시간 이후 정리하는 `storage:cleanup` 명령
- 활성 시스템 즉시 삭제, 고아 미디어 24시간, 암호화 백업 최대 30일의 운영 기준 문안
- Supabase 서울 리전 사용과 Google·Expo·Apple/Google Push 위탁 범위 표시

남은 확정:

- 사업자명, 대표자, 주소, 개인정보 보호 책임자
- 수탁자 법인명, 국가, 이전 시점·방법, 각 수탁자의 보유 기간
- 법정 보관 대상과 미성년자·위치기반서비스 적용 여부의 법률 검토

## 14. UGC 운영·미디어 보안 — 코드 완료, 운영 SLA 대기

구현 완료:

- 게시물·댓글·사용자 신고와 관리자 검토 상태, 신고자 처리 알림
- 사용자 차단 시 상호 팔로우 제거, 메시지 차단, 피드 게시물과 댓글 제외
- 게시물·댓글·탭톡·지식 피드백의 금칙어 1차 입력 필터
- 아바타 5MB, 게시·스토리 사진 15MB, 스토리 영상 50MB 및 MIME/종류 조합 검증
- 이미지 업로드 전 재인코딩으로 EXIF 제거, 비공개 버킷과 15분 서명 열람 URL
- 완료 API에서 Storage 객체의 실제 `Content-Type`·`Content-Length`와 파일 시그니처를 선언값과 대조
- 고아 미디어 정리 및 캐시 15분 기준

남은 운영 항목:

- 신고 처리 목표 시간, 경고·정지·삭제 단계, 이의제기 절차의 운영 정책 승인
- 영상 자체 검사·불법 이미지 해시 탐지 같은 고도화는 이용량과 위험도에 따라 외부 moderation 서비스 검토

## 15. 백업·복구·장애 모니터링 — 기반 완료, Secret·훈련 대기

구현 완료:

- `/health`와 DB 연결을 확인하는 `/ready` 분리
- `operations:health` 10초 제한 readiness 검사
- `pg_dump` custom format을 AES-256-GCM으로 암호화하는 `operations:backup`
- 운영 DB와 동일한 URL 사용을 거부하는 전용 복원 훈련 `operations:restore-test`
- GitHub Actions 15분 health check와 매일 암호화 백업 워크플로
- 로그의 인증·쿠키·비밀번호 제거와 요청 ID 기반 오류 응답

남은 실제 운영:

- GitHub Secret `DATABASE_URL`, `BACKUP_ENCRYPTION_KEY`와 변수 `GROOV_BACKUP_ENABLED=true` 등록
- 별도 복원 DB에서 월 1회 복원 훈련 후 결과 보관
- `GROOV_API_HEALTH_URL`, `GROOV_HEALTH_MONITOR_ENABLED=true` 등록
- Sentry 등 크래시·성능 수집 서비스 선정, 개인정보 검토와 DSN 연결
- Supabase DB 백업은 Storage 객체를 포함하지 않으므로 미디어의 별도 복제 대상과 비용 정책 결정

## 16. 스토어 등록자료·최종 출시 — 초안 완료, 외부 제출 대기

준비 완료:

- 앱명, Bundle ID, Android package, scheme, 버전·빌드 번호
- 한국어 부제·짧은 설명·상세 설명·키워드·지원 연락처 초안
- 개인정보·이용약관·계정 삭제 공개 URL
- Apple App Privacy / Google Data safety 입력용 데이터 목록
- 심사 메모, 실제 기기 검증표, 스크린샷·아이콘 요구사항 체크리스트

남은 외부 작업:

- GROOV 최종 1024×1024 아이콘, Android adaptive foreground, 스토어 규격별 최종 스크린샷
- Apple/Google 개발자 계정의 앱 등록, 서명·프로비저닝·업로드 키
- App Privacy, Data safety, Health apps declaration과 연령 등급 설문 제출
- 해당되는 신규 Google 개인 개발자 계정은 최소 12명의 테스터가 14일 연속 참여한 closed test 후 프로덕션 접근 신청

## 운영 명령

```text
pnpm --filter @moveall/api operations:health
pnpm --filter @moveall/api operations:backup
pnpm --filter @moveall/api operations:restore-test
pnpm --filter @moveall/api storage:cleanup
```
