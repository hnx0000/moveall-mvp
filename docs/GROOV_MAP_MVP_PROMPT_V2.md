# GROOV 지도 MVP 제작 프롬프트 V2

## 이 프롬프트의 목적

본 앱에 바로 적용하지 않는다. `prototypes/groov-map-mvp-v2`라는 완전히 독립된 지도 MVP를 제작하고, 사용자가 화면을 직접 만져본 뒤 채택한 지도만 본 앱으로 옮긴다.

이 MVP는 지도를 설명하는 소개 페이지가 아니다. 실행 즉시 실제 지도 화면이 보여야 하며, 러닝·등산·사이클·지역리그 지도를 한 번에 비교하고 조작할 수 있어야 한다.

## 마스터 제작 프롬프트

```text
GROOV 운동 앱을 위한 독립형 지도 MVP를 제작하라.

기존 GROOV 앱 코드는 수정하지 말고 별도의 프로토타입으로 만든다. 목적은 예쁜 가짜 지도 이미지를 만드는 것이 아니라, 실제 지도 데이터와 실제 GPS 경로를 이용하면서도 레퍼런스 이미지의 조형과 감성을 구현할 수 있는지 검증하는 것이다.

반드시 C:/Users/longr/OneDrive/문서/앱개발/개발자료 보관함/지도 제작 폴더의 1~12번 이미지를 직접 확인하고 다음과 같이 역할을 나눠 반영한다.

- 1, 5, 7, 10번: 지역리그의 구역별 게임 보드, 미니어처 판 두께, 지역 위에 설치되는 작은 랜드마크 피규어, 선택 지역의 빛과 깊이 표현에 사용한다.
- 2, 8번: 등산·사이클 지도의 등고선, 실제 고도 굴곡, 경로가 지형 위를 흐르는 3D 공간감에 사용한다.
- 6, 9, 11번: 펑키하고 게임스러운 GROOV HUD, 도트·격자·네트워크의 리듬, 선택 및 점수 반응 모션에 사용한다. 색상은 그대로 복제하지 않는다.
- 12번: 일반 기록 지도의 정보 절제, 넓은 여백, 도로와 경로가 즉시 구별되는 간결함에 사용한다.
- 3번: 복잡한 도심에서도 도로 위계를 읽을 수 있는 참고로만 사용한다. 정보량과 라벨 밀도는 그대로 따라 하지 않는다.
- 4번: 순위 역전이나 기록 완료 순간의 짧은 파티클 효과에만 사용한다. 지도 배경이나 상시 효과로 쓰지 않는다.

레퍼런스를 단순히 옆에 붙여놓거나 설명 카드에 표시하는 것은 반영으로 인정하지 않는다. 지도 표면, 카메라 시점, 지형의 깊이, 경로 표현, HUD, 지역 판, 랜드마크, 모션에 레퍼런스 특징이 실제로 나타나야 한다.

가장 중요한 원칙은 다음과 같다.

1. 가짜 도로와 임의의 네모 건물을 손으로 그려 지도처럼 보이게 만들지 않는다.
2. 실제 벡터 지도, 실제 위도·경도, 실제 행정구역 경계, 실제 DEM 고도 데이터를 사용한다.
3. GPS 경로만 샘플이어도 되지만 서울·한강·북한산 등 실제 지형 위에서 자연스럽게 이어지는 국내 좌표를 사용한다.
4. 지도 데이터가 로드되지 않으면 가짜 지도를 대신 보여주지 말고 명확한 오류 상태와 재시도 기능을 표시한다.
5. 지도 저작권 표시는 작게 정리하되 삭제하거나 가리지 않는다.
6. 첫 화면은 모바일 9:16 지도 전체화면이어야 한다. 데스크톱 설명 패널이나 거대한 제목을 먼저 보여주지 않는다.
7. 장식보다 지도와 GPS 경로가 먼저 읽혀야 한다.

전체 시각 방향은 ‘프리미엄 스포츠 게임의 지도’다. 귀엽고 펑키하지만 유아틱하거나 장난감 앱처럼 보이면 안 된다. 정교한 미니어처, 낮은 채도의 게임 보드, 빠른 운동 HUD, 선명한 단일 주황색 경로를 결합한다.

GROOV 색상은 다음을 사용한다.

- 화면 배경: #080706
- 지도 바탕: #100E0C / #171410
- 가장 어두운 그림자: #050403
- GROOV Orange: #FF5A30
- 밝은 Orange: #FF7A45
- 약한 Orange: #FFB08D
- 주 텍스트: #F4F0EA
- 보조 텍스트: #A69E96
- 비활성 경계·도로: #5A544E

앱의 모든 핵심 포인트 컬러는 주황색만 사용한다. 핑크, 보라, 청록, 형광 초록, 파랑 네온을 포인트 컬러로 사용하지 않는다. 물·공원·건물은 저채도의 흑연색, 회갈색, 매우 어두운 청회색 등 기능적 구분을 위한 색만 허용한다.

경로는 언제나 #FF5A30의 둥근 실선으로 표현한다. 경로 바깥에 2~3px의 어두운 외곽선을 두고, 현재 위치 주변에만 좁고 약한 주황 발광을 허용한다. 지도 전체를 빛나게 만들지 않는다.

MVP는 화면 상단의 작은 종목 전환 컨트롤로 다음 네 모드를 전환한다.

1. MOVE — 러닝·일반 기록용 실제 벡터 지도
2. TRAIL — 등고선과 실제 고도를 가진 등산 지도
3. RIDE — 주행 방향과 속도를 우선하는 사이클 지도
4. LEAGUE — 실제 행정구역 경계를 판으로 만든 지역리그 지도

각 모드는 동일한 지도에 색상만 바꾼 결과가 아니어야 한다. 정보 우선순위, 카메라, 지형, HUD, 조작 방식이 운동 목적에 맞게 달라야 한다.

MVP에서 반드시 직접 테스트할 수 있어야 하는 기능:

- 지도 드래그와 핀치 확대/축소
- 사용자가 움직인 카메라를 GPS 갱신이 강제로 되돌리지 않는 동작
- 현재 위치 추적 시작/해제
- 현재까지 기록된 전체 경로 보기
- 2D/3D 전환
- 실제 국내 좌표 위에서 샘플 GPS 기록 재생
- 경로가 추가되는 동안 거리·시간·속도 또는 고도 값의 변화
- 지역 선택
- 지역 점수 추가
- 점수 추가 후 순위, 참여율, 판 높이, 랜드마크 상태가 함께 변경되는 동작

웹 MVP 기술 기준:

- 실제 지도의 렌더링은 MapLibre GL JS 기반으로 한다.
- 베이스맵은 실제 벡터 타일을 사용하고 GROOV 전용 스타일로 재구성한다.
- 등산·사이클은 raster-dem 기반 실제 지형과 hillshade를 사용한다.
- 지역리그는 프로젝트에 이미 있는 실제 대한민국 시군구 SVG 경계 데이터를 읽어 사용한다.
- 샘플 GPS 경로는 GeoJSON LineString으로 관리한다.
- 로딩, 네트워크 실패, DEM 실패, WebGL 실패 상태를 만든다.
- DEM 또는 WebGL 사용이 불가능한 환경에서는 가짜 3D가 아니라 같은 데이터의 2D 등고선·힐셰이드 모드로 내려간다.
- 모바일 저사양 모드를 제공하고, 카메라 이동 중 불필요한 라벨과 효과를 줄인다.

절대 만들지 말아야 하는 결과:

- 손으로 그린 가짜 도로와 가짜 건물 블록
- 단순한 검정 배경 위에 주황 선만 올린 화면
- 일반 지도에 검은 필터만 씌운 화면
- 레퍼런스 썸네일을 나열한 소개 페이지
- 거대한 데스크톱 대시보드 안에 작은 휴대폰을 넣은 목업
- 지역 경계를 임의의 육각형이나 네모로 대체한 보드
- 실제 점수와 아무 관계없이 랜드마크가 움직이는 연출
- 청록·보라 네온을 사용한 흔한 사이버펑크 UI
- 라벨, 카드, 버튼이 지도의 절반 이상을 가리는 UI
- 상시 깜빡임, 과도한 글로우, 폭발 효과
```

## 화면 1 — MOVE / 러닝·일반 지도 프롬프트

```text
레퍼런스 12의 단순하고 호감 있는 지도 정보 구조를 기반으로 GROOV MOVE 지도를 제작하라.

실제 서울 지도와 실제 벡터 도로를 사용한다. 검토용 경로는 한강공원 또는 서울숲 인근의 실제 산책·러닝 도로를 따라 자연스럽게 이어지는 샘플 좌표로 만든다. 강을 가로질러 순간 이동하거나 건물 내부를 뚫지 않는다.

화면은 9:16 전체 지도다. 상단에는 작은 GROOV 로고, 러닝 아이콘, GPS 정확도만 둔다. 하단에는 거리, 시간, 평균 페이스를 한 줄 또는 낮은 반투명 HUD로 표시한다. 지도 중앙을 가리는 커다란 카드와 설명 문장은 넣지 않는다.

지도에서 남길 정보:

- 주요 도로
- 러닝 경로와 연결되는 보행로
- 강과 큰 공원
- 동네 이름
- 시작점, 현재 위치, 종료점

숨길 정보:

- 상점과 식당
- 주차장과 대중교통 아이콘
- 건물 이름
- 작은 도로 번호
- 운동 중 필요하지 않은 모든 POI

도로는 굵기와 밝기 차이로 위계를 구분한다. 물과 공원은 저채도로 표현한다. 실제 GPS 경로만 GROOV Orange로 표시한다. 출발점과 종료점은 S/F 문자가 들어간 작은 원으로 표현하며, 현재 위치는 중앙 점과 한 번 퍼지는 얇은 원형 파동으로 표현한다.

지도를 드래그한 뒤에는 자동 추적을 잠시 해제한다. 현재 위치 버튼을 다시 누를 때만 추적한다. 전체 경로 버튼을 누르면 모든 경로가 안전 여백 안에 들어오도록 부드럽게 이동한다.

완성 기준은 ‘지도 정보는 충분히 살아 있지만 처음 보는 순간 주황색 운동 경로부터 읽히는가’다.
```

## 화면 2 — TRAIL / 등산 지도 프롬프트

```text
레퍼런스 2와 8을 가장 강하게 반영하여 GROOV TRAIL 지도를 제작하라.

검토 위치는 북한산·관악산처럼 실제 높낮이가 확실한 국내 산악 지형을 사용한다. 실제 DEM 고도에 따라 산의 능선과 골짜기가 3D로 솟아야 한다. 검은 평면에 임의의 곡선을 여러 개 그려 등고선처럼 보이게 만드는 방식은 금지한다.

기본 카메라는 pitch 58~64도, bearing은 진행 방향을 기준으로 하되 사용자가 지도를 조작하면 고정한다. 지형 과장은 1.1~1.35 범위로 제한한다. 실제 산세를 읽을 수 있어야 하지만 과장된 판타지 산처럼 보이면 안 된다.

레퍼런스 2에서 가져올 요소:

- 얇고 정교한 등고선
- 어두운 표면과 밝은 경로의 대비
- 정보가 적고 고급스러운 지도

레퍼런스 8에서 가져올 요소:

- 지형의 능선과 골짜기를 명확히 읽는 깊이
- 경로가 지형 위를 타고 흐르는 공간감
- 3D 카메라가 주는 운동 몰입감

등고선은 10m 보조선, 50m 주 등고선으로 구분한다. 모든 등고선을 밝게 만들지 말고 보조선은 낮은 불투명도, 주 등고선만 조금 선명하게 만든다. 고도 숫자는 필요한 지점에만 드물게 표시한다.

GPS 경로는 지형 표면 위에 정확히 붙으며, 표면 아래로 파묻히거나 허공에 과도하게 떠 있으면 안 된다. 지나온 경로는 진한 주황색, 앞으로 갈 계획 경로가 있다면 낮은 불투명도의 주황 점선으로 구분한다. GPS가 끊긴 구간은 임의의 직선으로 연결하지 않는다.

운동 HUD는 현재 고도, 누적 상승, 경사도, 거리, 시간 중 세 값만 기본 표시한다. 상세 고도 프로필은 아래에서 살짝 올릴 때만 나타난다.

2D 전환 시에도 실제 지형 데이터에서 만든 등고선과 힐셰이드를 유지한다. 단순한 검정 평면으로 바뀌면 안 된다.

완성 기준은 ‘경로가 어느 능선을 타고 어느 골짜기를 지나는지 한눈에 읽히는가’다.
```

## 화면 3 — RIDE / 사이클 지도 프롬프트

```text
레퍼런스 6, 9, 11의 펑키한 게임 감성을 사용하되 실제 주행 중 읽기 쉬운 GROOV RIDE 지도를 제작하라.

검토 위치는 한강 자전거도로 또는 실제 국내 자전거도로를 사용한다. 경로는 실제 도로를 따라 이어져야 한다. 사이클 지도는 등산 지도보다 카메라 피치를 낮춘 38~46도로 설정하고, 현재 위치를 화면 중앙보다 아래에 두어 전방 경로를 더 많이 보여준다.

레퍼런스 6에서 가져올 요소:

- 지도 가장자리에 정리된 최소 HUD
- 현재 상태를 빠르게 읽는 게임 인터페이스

레퍼런스 9에서 가져올 요소:

- 도로 네트워크 속에서 경로가 명확하게 이어지는 방식
- 중요한 노드와 진행 방향을 강조하는 리듬

레퍼런스 11에서 가져올 요소:

- 그래픽 포스터 같은 자신감 있는 면 처리
- 제한적으로 사용한 도트와 하프톤 질감
- 지나치게 진지하지 않은 펑키한 분위기

도트·하프톤은 지도 위를 덮지 않고 HUD 가장자리, 로딩, 선택 상태에만 5~8% 불투명도로 사용한다. 청록·파랑·초록 네트워크 선은 사용하지 않는다. 모든 활성 경로와 노드는 주황색으로 통일한다.

속도를 가장 큰 숫자로 표시한다. 거리와 평균 속도는 두 번째 위계, 심박수는 세 번째 위계다. 텍스트는 주행 중 1초 이내에 읽을 수 있는 크기와 대비를 확보한다.

주행 중에는 진행 방향을 따라 카메라가 부드럽게 회전하지만, 작은 핸들 변화나 GPS 방위 노이즈에 따라 화면이 좌우로 흔들려서는 안 된다. 방향값을 스무딩한다. 사용자가 지도를 드래그하면 자동 카메라를 해제하고, 현재 위치 버튼을 누르면 3초 동안 부드럽게 복귀한다.

정차가 5초 이상 지속되면 주변 도로를 조금 넓게 보여주고, 출발하면 전방 중심 카메라로 복귀한다. 전체 경로 보기에서는 출발점부터 현재 위치까지 한 화면에 맞춘다.

완성 기준은 ‘빠르게 움직이는 상황에서도 다음 경로, 현재 속도, 전체 방향을 즉시 읽을 수 있는가’다.
```

## 화면 4 — LEAGUE / 지역리그 보드 프롬프트

```text
레퍼런스 1, 5, 7, 10을 가장 강하게 반영한 GROOV 지역리그 CITY BOARD를 제작하라.

실제 대한민국 시도·시군구 경계 데이터를 사용하고, 구역 모양을 임의의 육각형·네모·퍼즐 조각으로 바꾸지 않는다. 실제 지역 경계를 유지한 상태에서 각 지역을 두께가 있는 독립된 판처럼 표현한다.

카메라는 38~44도 아이소메트릭 시점이다. 지역 판은 무광 흑연 재질의 얇은 미니어처 보드이며, 측면은 표면보다 어둡다. 선택 지역과 상위 지역에만 주황색 가장자리 빛이 들어간다. 모든 지역을 주황색으로 칠하지 않는다.

레퍼런스 1에서 가져올 요소:

- 넓은 어둠 속에 떠 있는 정교한 지역 판
- 지역의 핵심 지점에 설치된 작은 주황 노드
- 사진처럼 느껴지는 얕은 심도와 미니어처 비례

레퍼런스 5에서 가져올 요소:

- 판 위에 쌓인 작은 도시 블록
- 지역과 경로가 실제 도시처럼 연결되는 깊이

레퍼런스 7에서 가져올 요소:

- 지도 위에 실제 피규어가 놓인 듯한 크기와 그림자
- 기록이 이동과 참여로 연결되는 게임 보드 감각

레퍼런스 10에서 가져올 요소:

- 대한민국 전체가 하나의 보드로 읽히는 구성
- 지역을 잇는 빛과 작은 거점
- 과도하지 않은 미니어처 월드의 호감도

판 높이와 표면 밝기는 실제 지역리그 점수와 연결한다. 점수가 높다고 판 전체가 거대한 탑처럼 솟지 않으며, 가장 낮은 지역과 가장 높은 지역의 높이 차이는 전체 판 두께의 약 1~1.8배 이내로 제한한다.

랜드마크는 실제 유명 건축물을 그대로 축소 복제하지 않는다. GROOV 자체 세계관의 운동 피규어를 만든다.

- 참여 시작: 작은 비콘 또는 깃발
- 일정 점수 도달: 러닝 게이트, 사이클 휠, 산악 피크, 스트렝스 토템
- 상위권: 미니 아레나
- 시즌 1위: GROOV CORE 타워

한 화면에 큰 랜드마크는 최대 3개, 작은 랜드마크까지 포함해 7개 이하만 노출한다. 나머지는 확대했을 때 나타난다. 피규어는 귀엽지만 머리가 과하게 크거나 유아용 장난감처럼 보이지 않게 한다. 표면은 무광 흑연과 반투명 주황 아크릴 재질을 사용한다.

지역을 누르면 선택 판이 4~6px 올라오고 얇은 주황 링이 한 번 퍼진다. 점수가 추가되면 판 높이, 참여율, 점수, 순위가 함께 갱신된다. 순위 역전 시에만 레퍼런스 4에서 가져온 주황색 삼각 파티클을 500ms 이내로 사용한다. 상시 파티클은 금지한다.

상단에는 시즌명과 남은 기간만 표시한다. 하단에는 선택 지역명, 등수, 점수, 참여 인원, 참여율, 바로 위 지역과의 격차를 한 카드에 표시한다. 지도 위에는 선택 지역과 상위 3개 지역 이름만 표시한다.

전국 보드에서 지역을 더블탭하면 해당 시도 보드로 들어가고, 다시 더블탭하면 시군구 상세로 들어간다. 드래그, 핀치 줌, 내 지역으로 이동, 전국 보기 기능을 제공한다.

완성 기준은 ‘실제 지역 경계와 실제 순위 시스템을 유지하면서도 운동으로 성장하는 하나의 게임 판처럼 느껴지는가’다.
```
